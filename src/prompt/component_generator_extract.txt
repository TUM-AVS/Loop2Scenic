1. Extract, don't generate.
Every statement in your output must come from <ORIGINAL_CODE>. Never invent Scenic code that is not already present.

2. Preserve semantics.
The extracted component should behave exactly like the original. Do not rewrite logic, simplify code, or change the scenario's behavior.

3. Adapt only when necessary.
You may make the smallest semantic-preserving modifications required to integrate with <ALREADY_EXTRACTED_COMPONENTS>, including:

- updating references after renaming
- removing duplicate definitions
- reusing equivalent definitions that already exist

Never modify code for readability or consistency alone.

4. Extract the minimum complete slice.
Include only the code required for the extracted component to work correctly, such as referenced behaviors, parameters, constants, spawn points, trajectories, or helper variables.

If one of these already exists in <ALREADY_EXTRACTED_COMPONENTS>, do not extract it again. Instead, reuse the existing definition.

5. When uncertain, extract less.
Do not include unrelated code simply because it is commonly associated with the requested aspect.
